MySQL · Teoría y ejercitación

Seis temas para pasar del dibujo a la base real: crear, insertar, consultar, relacionar y cruzar tablas. Cada tema tiene su pestaña 📘 Teoría y ✍️ Ejercitación.

Cómo se usa: escribí tus sentencias SQL en el cuadro y presioná Corregir. El corrector revisa la estructura del código (palabras clave, tablas, columnas y cláusulas): no ejecuta el SQL. Para probarlo de verdad, copialo en MySQL Workbench y ejecutalo con el rayo ⚡.

1 Crear la base y las tablas

Una base de datos es un contenedor de tablas. Primero se crea la base, después se elige con USE y recién ahí se crean las tablas. Cada tabla declara sus columnas con tipo y sus restricciones.

La receta mínima CREATE DATABASE tienda;
USE tienda;

CREATE TABLE clientes (
  dni INT PRIMARY KEY,
  nombre VARCHAR(50) NOT NULL,
  apellido VARCHAR(50) NOT NULL,
  telefono VARCHAR(20)
);
Tipos de dato que vas a usar
TipoGuardaEjemplo
INTNúmeros enterosdni, stock, cantidad
DECIMAL(10,2)Decimales exactos (10 dígitos, 2 decimales)precio, total
VARCHAR(50)Texto corto de hasta 50 caracteresnombre, telefono
DATEFecha con formato AAAA-MM-DD2026-03-02
TEXTTexto largoobservaciones
BOOLEANVerdadero o falso (1 / 0)activo
Restricciones que hacen la tabla confiable
RestricciónQué impone
PRIMARY KEYIdentifica cada fila: no se repite ni admite vacío.
AUTO_INCREMENTMySQL numera solo: 1, 2, 3…
NOT NULLObliga a cargar un valor.
UNIQUENo se repite, pero puede quedar vacío.
DEFAULT 0Valor automático si no se indica otro.
-- La tabla de productos, con clave automática.
CREATE TABLE productos (
    codigo    INT PRIMARY KEY AUTO_INCREMENT,
    nombre    VARCHAR(50) NOT NULL,
    precio    DECIMAL(10,2) NOT NULL,
    stock     INT DEFAULT 0
);
Buena práctica: nombres de tablas y columnas en minúscula, sin espacios, sin ñ y sin acentos. clientes sí; Clientes Nuevos no.
Orden importa: si una tabla tiene una FK, la tabla a la que apunta debe existir antes. Primero clientes y productos; después la intermedia compras.

2 Insertar datos con INSERT

Una tabla vacía no sirve de mucho. INSERT INTO agrega filas. Se indica la tabla, entre paréntesis las columnas y después VALUES con los datos en el mismo orden.

Una fila y varias filas INSERT INTO clientes (dni, nombre, apellido, telefono)
VALUES (30111222, 'Ana', 'Gómez', '11-5555-1111');

INSERT INTO productos (nombre, precio, stock) VALUES
('Muzzarella', 8500.50, 20),
('Napolitana', 9200.00, 15),
('Fugazzeta', 9900.75, 8);
Las reglas de oro del INSERT
  • Textos y fechas van entre comillas simples: 'Ana', '2026-03-02'.
  • Números van sin comillas: 8500.50, 20.
  • Los decimales se escriben con punto, no con coma: 8500.50.
  • Si la PK es AUTO_INCREMENT, no la escribas: MySQL la genera.
  • Un dato opcional desconocido se carga como NULL.
  • Podés insertar varias filas separándolas con comas y cerrando con ;.
Truco: si el INSERT falla, revisá en este orden: cantidad de columnas = cantidad de valores, comillas en los textos, punto en los decimales y que la PK no esté repetida.
Error clásico: escribir '8500,50' (con coma y comillas). Eso es un texto, no un número. Se escribe 8500.50.

3 Consultar: SELECT, WHERE y ORDER BY

SELECT es la sentencia que lee datos. No modifica nada: pregunta. Se combina con WHERE para filtrar, ORDER BY para ordenar, LIMIT para recortar y funciones como COUNT para resumir.

La estructura de una consulta SELECT columnas
FROM tabla
WHERE condición
ORDER BY columna ASC | DESC
LIMIT cantidad;
Las cláusulas, una por una
CláusulaPara qué sirveEjemplo
SELECT *Trae todas las columnasSELECT * FROM clientes;
SELECT col1, col2Trae solo esas columnasSELECT nombre, precio FROM productos;
WHEREFiltra filasWHERE precio > 9000
AND / ORCombina condicionesWHERE stock > 0 AND precio < 10000
LIKEBusca texto por patrónWHERE nombre LIKE '%zza%'
ORDER BYOrdena (ASC por defecto)ORDER BY precio DESC
LIMITRecorta la cantidad de filasLIMIT 3
ASRenombra una columna en el resultadoCOUNT(*) AS cantidad
Funciones de resumen
FunciónDevuelve
COUNT(*)La cantidad de filas
SUM(columna)La suma de los valores
AVG(columna)El promedio
MAX(columna) / MIN(columna)El mayor / el menor
-- Los tres productos más caros.
SELECT nombre, precio
FROM productos
ORDER BY precio DESC
LIMIT 3;

-- Cuántos clientes hay.
SELECT COUNT(*) AS cantidad
FROM clientes;
Para leer un resultado: primero mirá qué columnas pediste, después cuántas filas volvieron y por último en qué orden. Si el orden no te importa, igual conviene poner ORDER BY para que el resultado sea predecible.
NULL no es cero: para buscar vacíos se usa IS NULL, no = NULL. Y para los que tienen dato, IS NOT NULL.

4 Relaciones: FOREIGN KEY en acción

La FOREIGN KEY es la que convierte tablas sueltas en una base relacionada. Una FK en una tabla apunta a la PK de otra. En una relación 1:N va en el lado N; en una N:M aparece una tabla intermedia con dos FK.

La intermedia compras CREATE TABLE compras (
  id_compra INT PRIMARY KEY AUTO_INCREMENT,
  cliente_dni INT NOT NULL,
  producto_codigo INT NOT NULL,
  fecha DATE NOT NULL,
  cantidad INT NOT NULL,
  FOREIGN KEY (cliente_dni) REFERENCES clientes(dni),
  FOREIGN KEY (producto_codigo) REFERENCES productos(codigo)
);
Cómo se lee cada línea
LíneaQué significa
FOREIGN KEY (cliente_dni)La columna que guarda la referencia.
REFERENCES clientes(dni)El valor debe existir en la PK de clientes.
ON DELETE RESTRICTNo deja borrar un cliente que tiene compras.
ON DELETE CASCADESi se borra el cliente, se borran sus compras.
ON DELETE SET NULLSi se borra el cliente, la FK queda vacía.
Regla: la FK debe tener el mismo tipo que la PK a la que apunta. Si clientes.dni es INT, entonces compras.cliente_dni también es INT.
Error clásico: crear compras antes que clientes. MySQL rechaza la FK porque la tabla referenciada todavía no existe.
También se puede agregar después
ALTER TABLE compras
ADD CONSTRAINT fk_compra_cliente
FOREIGN KEY (cliente_dni) REFERENCES clientes(dni);

5 Consultas de varias tablas: JOIN

Los datos están repartidos: el nombre del cliente vive en clientes, el del producto en productos y la compra en compras. JOIN cruza las tablas usando las claves: por cada fila busca la que coincide con el ON.

El camino de las claves compras.cliente_dni    → clientes.dni
compras.producto_codigo → productos.codigo 
-- Cada compra con el nombre del cliente y del producto.
SELECT co.id_compra, cl.nombre AS cliente,
       p.nombre AS producto, co.fecha, co.cantidad
FROM compras co
JOIN clientes cl ON co.cliente_dni = cl.dni
JOIN productos p  ON co.producto_codigo = p.codigo;

Los tres tipos de JOIN que vas a necesitar
TipoQué devuelveCuándo se usa
JOIN (INNER)Solo las filas que coinciden en ambas tablas.Listar compras con su cliente.
LEFT JOINTodas las de la izquierda, aunque no tengan pareja.Clientes que nunca compraron.
RIGHT JOINTodas las de la derecha.Se usa menos; se puede invertir con LEFT.
Agrupar y calcular totales
SELECT cl.nombre, SUM(p.precio * co.cantidad) AS total
FROM clientes cl
JOIN compras co   ON co.cliente_dni = cl.dni
JOIN productos p  ON co.producto_codigo = p.codigo
GROUP BY cl.nombre
ORDER BY total DESC;

Clientes sin compras
SELECT cl.nombre
FROM clientes cl
LEFT JOIN compras co ON co.cliente_dni = cl.dni
WHERE co.id_compra IS NULL;
Truco de alias: usá nombres cortos (cl, co, p) para no repetir el nombre completo de la tabla en cada columna. El alias se declara una vez, al lado de la tabla.
Error clásico: olvidar el ON. Sin condición, MySQL combina cada fila con cada fila (producto cartesiano) y el resultado se llena de datos que no tienen nada que ver.

6 Práctica final: el script completo

Un script es todo el trabajo en un solo archivo: crear la base, crear las tablas en orden, cargar los datos y dejar las consultas listas. Se ejecuta de arriba hacia abajo con el rayo ⚡ de MySQL Workbench.

El orden que no se puede cambiar
  1. DROP DATABASE IF EXISTS (opcional, para empezar limpio).
  2. CREATE DATABASE + USE.
  3. Tablas sin FK: clientes y productos.
  4. Tabla con FK: compras (la intermedia).
  5. INSERT de clientes, productos y compras.
  6. Las consultas de lectura: SELECT, JOIN, GROUP BY.
Checklist antes de entregar ☐ La base se crea y se selecciona
☐ Las tres tablas existen y tienen PK
☐ compras tiene dos FK que apuntan a clientes y productos
☐ Hay datos en las tres tablas
☐ Al menos una consulta con JOIN
☐ Al menos una consulta con GROUP BY
☐ Todas las sentencias terminan con ;
Si el script falla a la mitad: leé el primer error, no el último. MySQL se detiene en la sentencia que no puede ejecutar y todo lo que sigue queda sin hacer.
